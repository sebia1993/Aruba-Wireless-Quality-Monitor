# Selected-detail response receipt archive (increment 1)

The protected Windows service can optionally archive the existing sanitized D03/D04/D07/D08 observations, including accepted responses that finish before orderly shutdown drains its executor. This is a developer-side bounded trial facility, not the full v1 retention or incident-correlation design.

- Default off. In the existing ACL-protected service configuration directory, an authorized local administrator may provide `selected-history.json` containing exactly `{"version":1,"enabled":true,"policy":"bounded-selected-receipts-v1"}`. This does not enable any CLI or replace the separate per-command and Radio approvals.
- Each successful, revalidated selected response yields a private immutable receipt with command, controller, AP binding, connection instance/generation, approval provenance, command start and receipt time. Measurement times and counter epoch remain null. No raw CLI, AP IP, raw wired MAC, SSH key, username or client data is copied. The binding and AP name are private operational identifiers, not anonymous public data.
- The Engine alone commits receipts to `core.db`, using the existing Store lock and FULL SQLite transaction. Exact ID replay is idempotent; a conflicting payload is rejected. Failure retains a bounded in-memory pending receipt per worker and stops dispatch using the existing storage-error path. Explicit storage recovery retries the same receipt. During orderly shutdown the Engine waits for its existing executor to stop, harvests completed selected receipts (not other current-state observations), and saves them through the same idempotent single-writer path, with a fresh disk protection check per receipt. Cancelled futures are ignored. An existing storage error, a new write error, critical disk or an unavailable worker result prevents a clean service-stop status; known unsaved receipts remain pending in memory and SSH workers still close. No new collection, implicit storage recovery or automatic deletion occurs. A crash or failed shutdown before commit can still lose pending evidence; durable spool/replay across restarts remains outstanding.
- The private Store-side receipt history query requires an exact controller and approved command, a half-open receipt-time range of at most 30 days, and returns up to 20 receipts with an ascending (receipt time, receipt ID) keyset cursor. The composite index bounds lookup; same-second receipts remain distinct. It is not a snapshot across pages, so late inserts before a cursor may be missed. The range is a query bound, not a retention guarantee. No unrestricted public API or SSH activity is added. Lifecycle-aware full historical presentation/export remains future work.
- Existing core online backups include the receipt table. The private archive is not returned to browsers; the administrator-only historical index described below returns a narrow masked receipt summary, not the payload. No export, history-based cause, Down, measured Airtime, counter delta, or field-validation inference. The operations projection includes categorical pending/error state only.
- The archive has a fixed 50,000 receipt / 128 MiB encoded-payload ceiling (not physical database size) and 128 KiB per receipt. At capacity it fails closed without deleting records, using the existing storage protection path. Do not enable for unattended production until evidence-aware expiration, bounded historical query/export, recovery and disk lifecycle are implemented. Disabling the local policy at service restart does not remove existing receipts.
- All existing selected command cadence, priority, CPU/time budget, peer-veto, and authorization checks remain unchanged. No field validation or release approval is established by this increment.

## Administrator historical receipt index (bounded read-only API)

`GET /api/admin/selected-history?controller=w1&command=D07&start=1000&end=1001` uses the existing authenticated HTTPS administrator session, no new account or permission. The archive must be locally enabled; only currently configured logical controller IDs are in scope. Command is one of D03, D04, D07, D08, never a CLI string. Integer Unix-second bounds are half-open receipt time, at most 30 days; optional limit 1–20 (default 20). To advance, pass both `after_time` and `after_id` from `next_cursor`. The cursor's random receipt ID is used for stable ordering, not AP identity or authorization. It is not a snapshot across pages. A disabled archive returns enabled=false, not proof of no history.

Each row contains a view-instance-keyed AP token (not a persistent identity, AP name or raw binding), receipt time, explicit unvalidated/unknown flags and allowlisted counts of retained/reported detail rows or D03 requested Radio and reported field counts. No raw payload, AP names, connection IDs, approvals, MACs, credentials or metric values are disclosed. Counts describe records, not AP status, verified coverage or completeness. Invalid archived provenance fails closed rather than yielding a plausible normal observation. The request is audited categorically before disclosure without recording query values or cursor; audit/storage failure returns 503. Unauthenticated requests receive 401, non-admins 403, invalid enabled queries 400. Existing HTTPS Host/session/cache controls apply. No collection, write to archive, metric-level export or retention change. The owner must still complete actual environment validation. This read model is an intermediate index for later authorized detailed history, not FR-09 completion.

## Administrator browser index

The existing operations management menu shows the selected-detail history panel only for administrator sessions. Enter a currently configured logical WLC ID, select D03/D04/D07/D08 and a receipt-time lookback of 1 hour, 24 hours, 7 days or 30 days. An explicit query freezes the half-open time bounds (KST display, end excluded) for cursor paging, 20 rows at a time. Change any filter or query again to clear the previous results and restart; an error, disabled archive, or empty page is labeled separately. The display uses only the masked token and command-specific counts returned by the existing audited HTTPS API. No automatic polling, CLI, raw identities, sample-time or health/cause claim, export, or additional authority. Tokens are view-instance scoped, not persistent AP identifiers. Results across pages are not a snapshot. Browser visibility is not authorization: the server still denies non-admin requests. Actual Chromium regression exercises admin pagination, identical bounds, role denial, private-field masking, filter reset, invalid scope and disabled archive. No production validation inferred.
