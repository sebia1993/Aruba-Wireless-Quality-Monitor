# Selected-detail response receipt archive (increment 1)

The protected Windows service can optionally archive the existing sanitized D03/D04/D07/D08 observations, including accepted responses that finish before orderly shutdown drains its executor. This is a developer-side bounded trial facility, not the full v1 retention or incident-correlation design.

- Default off. In the existing ACL-protected service configuration directory, an authorized local administrator may provide `selected-history.json` containing exactly `{"version":1,"enabled":true,"policy":"bounded-selected-receipts-v1"}`. This does not enable any CLI or replace the separate per-command and Radio approvals.
- Each successful, revalidated selected response yields a private immutable receipt with command, controller, AP binding, connection instance/generation, approval provenance, command start and receipt time. Measurement times and counter epoch remain null. No raw CLI, AP IP, raw wired MAC, SSH key, username or client data is copied. The binding and AP name are private operational identifiers, not anonymous public data.
- The Engine alone commits receipts to `core.db`, using the existing Store lock and FULL SQLite transaction. Exact ID replay is idempotent; a conflicting payload is rejected. Failure retains a bounded in-memory pending receipt per worker and stops dispatch using the existing storage-error path. Explicit storage recovery retries the same receipt. During orderly shutdown the Engine waits for its existing executor to stop, harvests completed selected receipts (not other current-state observations), and saves them through the same idempotent single-writer path, with a fresh disk protection check per receipt. Cancelled futures are ignored. An existing storage error, a new write error, critical disk or an unavailable worker result prevents a clean service-stop status; known unsaved receipts remain pending in memory and SSH workers still close. No new collection, implicit storage recovery or automatic deletion occurs. A crash or failed shutdown before commit can still lose pending evidence; durable spool/replay across restarts remains outstanding.
- The private Store-side receipt history query requires an exact controller and approved command, a half-open receipt-time range of at most 30 days, and returns up to 20 receipts with an ascending (receipt time, receipt ID) keyset cursor. The composite index bounds lookup; same-second receipts remain distinct. It is not a snapshot across pages, so late inserts before a cursor may be missed. The range is a query bound, not a retention guarantee. No unrestricted public API or SSH activity is added. Lifecycle-aware full historical presentation/export remains future work.
- Existing core online backups include the receipt table. The private archive is not returned to browsers; the administrator-only historical index described below returns a narrow masked receipt summary, not the payload. No export, history-based cause, Down, measured Airtime, counter delta, or field-validation inference. The operations projection includes categorical pending/error state only.
- The archive has a fixed 50,000 receipt / 128 MiB encoded-payload ceiling (not physical database size) and 128 KiB per receipt. At capacity it fails closed without deleting records, using the existing storage protection path. Do not enable for unattended production until evidence-aware expiration, bounded historical query/export, recovery and disk lifecycle are implemented. Disabling the local policy at service restart does not remove existing receipts.
- All existing selected command cadence, priority, CPU/time budget, peer-veto, and authorization checks remain unchanged. No field validation or release approval is established by this increment.

## Administrator historical receipt index (bounded read-only API)

`GET /api/admin/selected-history?controller=w1&command=D07&start=1000&end=1001` uses the existing authenticated HTTPS administrator session, no new account or permission. The archive must be locally enabled; only currently configured logical controller IDs are in scope. Command is one of D03, D04, D07, D08, never a CLI string. Integer Unix-second bounds are half-open receipt time, at most 30 days; optional limit 1–20 (default 20). To advance, pass both `after_time` and `after_id` from `next_cursor`. The cursor's random receipt ID is used for stable ordering, not AP identity or authorization. It is not a snapshot across pages. A disabled archive returns enabled=false, not proof of no history.

Each row contains a view-instance-keyed AP token (not a persistent identity, AP name or raw binding), receipt time, explicit unvalidated/unknown flags and allowlisted counts of retained/reported detail rows or D03 requested Radio and reported field counts. No raw payload, AP names, connection IDs, approvals, MACs or credentials are disclosed. D03, D04, D07 and D08 include the fixed reported-value subsets described below. Counts describe records, not AP status, verified coverage or completeness. Invalid archived provenance fails closed rather than yielding a plausible normal observation. The request is audited categorically before disclosure without recording query values or cursor; audit/storage failure returns 503. Unauthenticated requests receive 401, non-admins 403, invalid enabled queries 400. Existing HTTPS Host/session/cache controls apply. No collection, write to archive, metric-level export or retention change. The owner must still complete actual environment validation. This read model is an intermediate index for later authorized detailed history, not FR-09 completion.

## Durable Engine-side staging (bounded restart replay)

When explicitly enabled, the Engine stages already harvested accepted receipts in a private core SQLite queue (one per logical WLC, at most four, each <=128 KiB), with FULL transactions and existing Store locking. It stages before archive writes and checks fresh disk protection before both steps. Archive insertion or exact replay and acknowledgement of the matching queued copy are one transaction; conflicting IDs/payloads and capacity failure retain pending evidence and freeze dispatch. On a new enabled Engine, load the bounded queue before scheduling and retry the exact receipts; a removed/unavailable configured controller blocks startup rather than silently discarding its pending record. Disabled policy does not replay or remove pending evidence. Pending records are not exposed by historical queries and are included in existing core backup. No extra SSH, current-state publication from replay, change to archive retention, or implicit validation. This covers a failure/crash after durable staging, NOT a worker response or in-memory harvest interrupted before the first successful stage. Disk/write failure can still prevent staging; never claim full crash-loss prevention. Further worker-to-writer durable handoff, lifecycle/retention and actual environment validation remain open.

## Rolling historical disclosure window (not physical expiration)

The audited administrator selected-history API now applies a server-clock rolling 30-day receipt-time disclosure floor to every validated query and cursor page, including restored core backups. The original request remains bounded and validated; SQL restricts its effective start to the greater of the requested start and the current floor. Expired cursor rows do not invalidate valid forward paging or reopen expired history. The response carries the floor and a restriction flag; the browser explicitly labels restricted periods rather than claiming absence, and rejects rows outside the permitted interval. The private archive/backup/pending queue is unchanged and no data is deleted. This is an intermediate disclosure safeguard, not complete retention, verified physical erasure, prevention of screenshots/prior copies, or protection against a misconfigured or rolled-back server clock. Shorter site-specific retention and evidence-aware expiration/backup lifecycle remain outstanding. Actual synthetic worker/SQLite, backup restore, authenticated HTTPS and Chromium regression coverage added. No new CLI, credentials, permissions or release changes.


## Early bounded worker-to-writer handoff

The enabled Engine now accepts the immutable selected receipt immediately after the worker tick and before snapshot/cluster/user-frame construction. A private one-slot-per-controller memory mailbox (maximum four) is drained by the existing coordinator even while the worker future is incomplete or its frame construction fails. The worker does not access SQLite or hold the coordinator lock. The successful handoff removes the receipt from the returned Reading to avoid redundant processing. The same coordinator stages and archives under existing storage/disk limits and freezes dispatch on a write failure. On orderly close, drain the mailbox after executor shutdown and preserve the existing failed-stop outcome for unavailable worker results. A staged receipt survives restart; a mailbox-only receipt may still be lost on abrupt process termination or disk failure before durable staging. No additional CLI, field acceptance, current-state publication, permission changes or evidence deletion. Tests exercise real synthetic executor paths with a delayed/failing snapshot, stage/save failure and explicit recovery, and close after frame failure. Exact new CI is required.

## D03 conservative reported-counter boundary hints

The selected Radio worker compares only the immediately preceding still-retained accepted observation for the same exact requested Radio and immutable approved source context. Comparison requires a strictly positive receipt gap of at most 120 seconds; it never resurrects withdrawn or expired live data, bridges a failed attempt or uses a different requested Radio. The previous record is consumed in the new attempt and any pending comparison input is cleared on session reset. Compare only reported Radio reset, TX timeout and RX CRC error counts, using exact uint64 integers, not floating point. A decrease takes priority over a reported reset-count increase; missing pairs cannot prove absence, and all three pairs must be available to label no boundary observed. Legacy or incomparable records explicitly remain not assessed. This is a categorical boundary hint only, not physical reset verification, counter wrap correction, an actual Counter Epoch, measurement time, delta, rate, Airtime, health or cause. The existing admin live and archived views show the fixed enum (unknown stored values fail closed); receipt-time archives preserve the hint without raw comparison input, extra SSH, new permissions or deletions. Synthetic worker/Engine/SQLite, invalid archived enum and real Chromium regressions added; exact full CI required.
