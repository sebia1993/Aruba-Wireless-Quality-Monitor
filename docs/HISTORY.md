# v0.7.0-dev: client observations and historical reports

Fixture-engine detailed Client Table records are checked against unique current AP/Radio/BSSID/SSID/active association and generation. Stored in a synthetic-only SQLite ledger. Latest detail samples are not the whole active-client count. Missing observations never imply disconnection. Link quality is partial without a valid retry interval. Station Stats uses its own counter intervals and association context; its ratio is displayed separately, not used in mismatched Client Table intervals. Actual Airtime and cause are not asserted. Automatic Station Stats reservations are bounded to three eligible active clients per AP result and remain simulation-only.

Radio history query accepts one observed Radio, start inclusive/end exclusive epoch seconds, raw/5m/1h resolution, maximum 7/30/365 days and 2000 rows. UI uses KST. No missing buckets are synthesized, invalidated aggregate days omitted. CSV contains provenance, range and resolution, safeguards text formula prefixes; HTML escapes values. Demo-only endpoints and data; exports are not production incident reports. Actual RBAC, PII/audit and report validation remain release gates. The demo uses a temporary directory; automatic long-term retention/aggregation and real-data storage remain pending.
