# v0.6.0-dev fixture-engine demo

Run AWQM.exe --engine-demo. Only invented CLI responses are used; no network connections or real device inputs. Browser listens only on 127.0.0.1. Job API requires exact same-origin and per-process demo token and restricts targets to observed synthetic APs. This is not Aruba authentication or production HTTPS.

The fixture workers use the same scheduler, parsing, merge, SQLite and job path. WLC offsets are 0/15/30/45s. First samples may take time to appear; three risk observations are needed for automatic selection. Per-WLC max 5 active APs, max 2 newly reserved per round, 60s cooldown. CPU and time limits and current target checks still govern actual job execution. Manual reservation is idempotent; job status and cancel are shown in AP detail and administration. In-memory receipts or optional SQLite receipts use epoch time. Restart makes interrupted running jobs failed/unknown and unexpired queued jobs revalidate. Demo DB and receipts are temporary by design; durability is verified separately against persistent directories. Automatic selection remains disabled for unvalidated real observations. Detailed client result history, actual continuous operation, authentication and Windows Service are not completed.
