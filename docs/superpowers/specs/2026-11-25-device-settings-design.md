# 앱에서 실제 장비 등록과 조회

## 사용자가 하려는 일

Windows에서 AWQM을 열고 장비를 등록한 뒤, 그 장비가 반환하는 무선 정보를 같은 프로그램에서 확인한다. 기본 창과 처음 열리는 대시보드에서 장비 설정 위치를 바로 찾을 수 있어야 한다.

## 설정과 첫 조회

- 기본 창에 **장비 설정**, 로컬 대시보드에 **설정 → 실제 장비**를 둔다. 두 진입점이 같은 설정 화면을 연다. 브라우저에서 보낸 요청만으로 장비 설정이나 자격 증명을 변경할 수 없도록 한다.
- 한 화면에서 등록한 WLC를 추가·수정·삭제한다. 기존 수집기가 지원하는 최대 네 대까지 관리 IP와 조회 계정을 개별 등록한다. 기본 SSH 포트는 22다.
- 기존에 신뢰한 SSH 키를 먼저 찾는다. 등록된 키가 없으면 관리자가 별도 경로로 확인한 SHA-256 장비 지문을 붙여넣거나 신뢰한 키 파일을 선택한다. 연결 상대의 키를 확인한 후 로그인한다. 키가 바뀌면 연결을 멈추고 화면에 이유를 표시한다.
- 비밀번호는 로컬 앱에서만 입력한다. 기본은 현재 실행 동안 사용하고 사용자가 저장을 선택하면 해당 Windows 계정의 DPAPI로 보호한다. 프로필을 삭제하면 저장한 비밀번호도 지운다.
- **연결 테스트**에 인증 성공 여부와 조회 권한·지원 명령 확인 결과를 나누어 표시한다. **저장하고 모니터링**을 누르면 앱이 실행되는 동안 지원 항목을 갱신한다. 중지 버튼과 마지막 관측 시각을 제공한다. 로컬 장비가 등록된 PC에서는 다음 실행 때 장비 목록을 먼저 보여주고, 비밀번호를 저장하지 않았으면 앱에서 다시 입력한다. 관리자가 지정한 운영 주소가 있으면 기존 운영 대시보드를 우선한다.

## 결과 화면

- 장비별 연결 상태·CPU, AP 목록과 활성 상태, Radio의 대역·채널·이용률·간섭·노이즈, SSID/BSSID와 관측된 연결 수를 해당 명령이 반환한 범위에서 보여준다. 관측 실패·권한 부족·명령 미지원은 구분하고, 실제 조회 결과에 모의 값을 채워 넣지 않는다.
- 승인된 운영 HTTPS 대시보드는 기존 로그인과 역할로 연다. 서비스의 클러스터·AP 앵커, WLC 메모리·데이터 경로, 주변 Radio, 단말 상세·이력과 품질 점수는 기존 역할·현장 승인·장비 지원 상태를 따른다. 앱 안에서 해당 항목으로 접근하는 위치와 사용 가능 조건을 알 수 있어야 한다. 현 버전에서 구현하지 않은 실제 단말 Airtime은 미지원으로 표시한다. 장비에 접속한 사실만으로 검증 완료로 처리하지 않는다.
- 실제 조회 데이터와 비밀번호는 기존 무인증 모의 웹 서버에 싣지 않는다. 현재 Windows 사용자의 화면에서 조회하거나 기존 인증된 운영 화면으로 연결한다.

## 수집 방식과 운영 범위

기본안은 일반 사용자 PC에서 앱을 열어 둔 동안 읽기 전용으로 수집하는 방식이다. 파일 편집, 서비스 계정, TLS 웹 서버 설정이 필요 없다. 이미 설치된 서비스는 독립적으로 운영된다. 대안은 같은 설정 메뉴에 백그라운드 Windows 서비스 설치와 구성까지 넣는 방식이다. 로그아웃 후에도 수집하고 이력을 누적할 수 있으며, 관리자 권한과 전용 서비스 계정으로 한 번 설정해야 한다. 이 대안을 이번 변경에 포함할지는 사용자 선택이다.

## 확인 기준

1. 새 사용자 프로필로 최종 Windows 설치 파일을 열어 첫 화면에서 설정을 찾는다.
2. 로컬 SSH 시험 장비로 등록·키 확인·연결·실측 표 갱신·중지·재실행을 확인한다. 키 불일치 시 비밀번호를 전송하지 않고, 틀린 자격 증명을 자동 반복하지 않는다.
3. 권한 부족, 명령 미지원, 장비 오프라인, 관측치 없음과 예시 데이터 상태가 각각 구분되는지 확인한다.
4. 기존 운영 대시보드 및 서비스의 시작·중지, 보호된 설정, 단일 EXE 배포를 회귀 검증한다. 실제 장비 호환성은 현장에서 관측한 결과로 기록한다.
